### 踩坑记录：trim 脚本会吃掉「次核心段」，合并成一个单段才对

第一版草稿把 Friday 与 Lil Pig 两段分成两个自然段，
`trim_learning_section.py` 报「删掉 1 段」—— 它的规则是
**保留最长的非对策段、删掉较短的那段**（铺垫信息量最低）。
结果 Lil Pig 那半（「记忆是素材不是身份」）被整段删掉。

→ 修法：**把两个论点合并进同一个自然段**（用「；」连接，不用换行），
  再按 200 字预算压缩措辞。现在 193 汉字、无需裁剪、两半都在。
  → 教训：**这个脚本的「删段」判据是「长度」，不是「重要性」** ——
    内容重要但写得短的段落会被当成铺垫删掉。

### 另一个坑：`openclaw memory index --force` 撞 embedding RPM 限流

清掉 embedding cache 后重建索引，MiniMax 侧返回
`rate limit exceeded(RPM)` → 索引失败。
但 `memory status --deep` 仍报 `133/133 files · Dirty: no` ——
**「Dirty: no」不代表新文件已入库**，它是增量状态位，不是完整性断言。
→ 重试一次（sleep 45s）后成功；新文件（E88.md）随即能被搜到且排第 1。
