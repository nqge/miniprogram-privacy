### E52：快照管不住退化 —— 递增是趋势，快照看不见

> 本条讲：**快照管不住退化 —— 递增是趋势，快照看不见**

**发现时间**: 2026-10-28 08:0x

## 现象

今晨巡检后手查 healthcheck 的 run history，发现耗时在**无修改**地爬升：

| 时间 | 耗时 |
|---|---|
| 10-26 10:52 | **27s** |
| 10-26 17:10 | 214s |
| 10-27 07:00 | 298s |
| 10-28 07:00 | **378s** |

不到两天涨了 **13.9 倍**。按每次 +80s 的斜率外推，**10-31 前后撞 600s timeout**。

## 陷阱一：把「我加的」和「它自己变的」混成一条线

我最初的归因是「provider 变慢」或「CPU 争抢」。查 run history 才发现——
**10-26 那两次跑的根本不是同一份代码**：27s 那次是我手动跑的旧版本，
214s 那次是当天下午加完断言组之后的 cron。

所以曲线里混着**两种增长**：

1. **我加组**（有意为之）：断言组从 20 组加到 26 组 → 每组都要跑 → 自然更慢
2. **每组自身变慢**（退化）：这才是真正要盯的

**混成一条线去外推，就会得出「再调高 timeout 就行」的错误结论** ——
那只是把退化藏起来，等下一次「变化」重新解释曲线。

> **通用判据**：看到一条单调递增的曲线，先问
> **「这几次运行之间，代码变了吗？」**
> 变了 → 是我加的（可接受）；没变 → 是它自己退化（要查）。

## 陷阱二：占用率断言是快照，递增是趋势

【U】组管的是「最近一次耗时 / timeout 是多少」——那是**快照**。
快照在 50% 时是 PASS，趋势到 100% 才是 FAIL。

**中间这 3 天完全没人看见。**

| | 问的问题 | 能在什么时候发现问题 |
|---|---|---|
| 快照 | 最近一次占比多少 | 已经撞上时 |
| 趋势 | 最近 N 次是不是在涨 | **涨的过程中** |

> **快照只能在终点报警，趋势才能在途中报警。**
> 一个只会看「当前值」的监控，对**渐进式退化是盲的**。

## ✅ 解法：给【U】组加一条趋势判定

判据：最近 3 次耗时**单调递增**且最新一次 > 50% timeout → WARN。

- 单调性要求：避免「抖动」被误判成趋势
- 涨幅门槛：避免日常 ±10% 的正常波动刷屏
- 报 WARN 而非 FAIL：退化还不致命，但**值得现在看一眼**

## ⚠️ 更正记录（2026-10-28 09:4x，心跳复核时发现）

**本条初版写「趋势判定缺失，待加」，这是错的 —— 该判定早已存在且正在生效。**

| 项 | 事实 |
|---|---|
| 首次引入 | `d2fedcb`（2026-10-27，新增【U】组时**自带**趋势判定） |
| 代码位置 | `scripts/healthcheck.sh`【U】组：`if recent[0] < recent[1] < recent[2] and recent[2]/1000.0/tsec > 0.5` |
| 实证 | 2026-10-28 07:00 cron 与 07:5x 手动跑**都真的报了这条 WARN**：`healthcheck 最近 3 次耗时递增 207s→298s→378s(超时 600s)-- 在长` |
| 本地复算 | 真实序列 207s→298s→378s、timeout 600s → 条件求值为 True |

**错在哪**：初版只看了【U】组的「快照」那一半（`ratio > 0.7` → FAIL），
**没往下读到相邻的 `trend_warn` 分支**，就断言「趋势那条缺失」。
更糟的是 09:00 的 daily-learning 又把这个误判写成「未落地（需定夺）」，
等于**错误结论进了 L1 库**。

**教训（比原判据更值钱）**：
1. **断言「某机制缺失」之前，先 grep 实现** —— 同一个函数里相邻分支经常已经有你要的东西
2. 「我打算加」和「它已经在跑」之间，差别是一次 `grep -n` 和一次**看真实输出**
3. **L1 条目里的「待办」会被下一个会话当既成事实继承** —— 写进去之前先验证它真的没做
4. 这次是靠**手动复算判据 + 核对历史输出**才发现的，**不是靠读代码读出来的**

> 原文中「趋势（缺的那条）」这个说法已改为「趋势」；本条其余洞察
> （快照 vs 趋势、「先问代码变没变」）**依然成立且有价值**，予以保留。
