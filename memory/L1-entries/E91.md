### E91：同一个状态标签下要留证据分级，状态相等不等于证据相等
> 本条讲：**同一个状态标签下要留证据分级，状态相等不等于证据相等**

**核心断言**：一个状态字段（`state` / `status` / `result`）如果把**推断结论**、
**字符串匹配**和**原始凭据**三种不同强度的证据压成同一个标签，
那么**所有只读这个标签的判据都会把它们当成等价事件**——
统计口径一旦按标签聚合，弱证据就会冒充强证据，把阈值和告警一起带偏。
**状态相等 ≠ 证据相等。**

> **分类**：认知与判断 / 日志与状态设计
> **首次记录**：2026-11-28
> **来源**：`memory/quota-history.jsonl` 逐条归日统计 + 三个脚本源码比对

---

## 场景

任何**事件日志 + 按标签聚合统计**的结构 —— 监控告警、任务失败计数、
额度消耗天数、错误分类、审计流水。

典型症状：统计出来的「某类事件发生了 N 次」看着很像真事，
但你**无法回答「这 N 次里，有几次是亲眼见到原始证据的」**。

## 陷阱

**陷阱 1：一个 `state` 字段装了三种证据强度**

实测（2026-11-28）`memory/quota-history.jsonl` 里同一个 `state: quota_exhausted`
底下藏着三种完全不同的 `detail`：

| 时间段 | `detail` 内容 | 证据强度 | 来源 |
|---|---|---|---|
| 10-26 ~ 11-09 | 「**没有任何可用 provider** —— 整个系统无法推理」 | **推断结论** | 下游脚本的二手措辞 |
| 11-10 ~ 11-23 | 「额度特征命中」 | **字符串匹配** | 只知道命中了关键词，不知道命中在哪 |
| 11-27 | 「⚠️ WARN minimax 限流（HTTP 429）…已达到 Token Plan 用量上限…(2056)」 | **原始凭据** | 上游返回的原始报错 |

更糟的是：这三个 `detail` **分别来自三个不同的脚本/时期**
（`backfill_quota_history.py` 的回填、`record_quota_probe.py` 的默认值、
`check_provider_health.py` 的原始输出），
但**写进同一份日志时字段名完全一样**。

**陷阱 2：下游判据只读 `state`，从不读 `detail`**

`scripts/check_quota_sustained.py`（额度持续性判据真身）读日志时：

```python
out.append((day.isoformat(), str(d.get("state") or "other_fail"), str(d.get("detail") or "")))
...
if state == "quota_exhausted":   # ← 只看 state
```

→ 一次**普通限流**（`check_provider_health.py` 自己把 HTTP 429 归为 `warn`，
只有 HTTP 402 才是「配额耗尽」）和一次**真实额度耗尽**，
被算成**同一种「耗尽日」**。

后果直接可见：今天 07:00 的巡检报「最近 7 天里有 3 天额度耗尽
（2026-11-22、2026-11-23、2026-11-27）」，
但 11-27 那条的 `detail` 是**限流**、11-22/11-23 的 `detail` 是**「额度特征命中」**——
三者都**没有一条带原始的 Token Plan 报错**。
→ **「3 天额度耗尽」这个结论，是被标签推出来的，不是被证据推出来的。**

**陷阱 3：补一个 `detail` 字段不叫「留证据」**

只补字段名不解决问题 —— 判据没被改成读它，字段就只是**装饰**。
证据分级要能**一路影响到聚合口径**才算落地。

## 岔路口

| 岔路口 | 选 A | 选 B | 为什么 |
|---|---|---|---|
| 状态标签 | 一个 `state` 装所有事 | `state` + **证据等级字段** | B 才能让聚合区分强弱证据 |
| 证据等级怎么定 | 手工按措辞猜 | **记录时写死「证据来源」**（原始报错 / 匹配命中 / 推断结论） | 手工分类会被历史数据打脸 |
| 聚合口径 | 按 `state` 数天数 | **只认带原始凭据的那批** | 否则阈值形同虚设 |
| 历史数据 | 全部当同等 | **按证据等级降级处理**，或标注「不可判定」 | 旧记录不该被追认成强证据 |
| 改动位置 | 在消费端加 if | **在写入端标好等级** | 消费端只能过滤已有标签，过滤不出没写进去的证据 |

**关键判据**：当你要回答「这 N 次里，有几次是**亲眼见到原始证据**的」——
如果你答不上来，说明**证据分级没有落地**，只是加了个字段。

## 与相邻条目的边界

- **E90**（判据要分级信号强度）讲的是**告警的强度分级**（观察信号 vs 行动信号）；
  本条讲的是**事件记录本身的证据强度**（推断 vs 匹配 vs 原始凭据）。
  一个管输出端的措辞，一个管输入端的数据 —— 两者都在「分级」，但分的是不同的东西。
- **E85**（时间戳基准要统一）讲的是**同一个字段的格式一致性**；
  本条讲的是**不同字段语义被塞进同一个标签** —— 前者是「写法乱」，后者是「含义乱」。
- **E66**（长期项不该天天告警）讲的是**告警去重**；
  本条指出：即使不告警，**统计口径本身仍可能被弱证据污染** —— 安静地错比吵着错更隐蔽。

## 可立即执行的对策

给状态日志的每条记录标上证据来源，判据统计耗尽天数时只认带原始凭据的那些，
别让推断和匹配冒充证据。
