### E48：分类不该等于过滤 —— 「分组」顺手造出来的盲区

> 本条讲：**分类不该等于过滤 —— 「分组」顺手造出来的盲区**

**场景**：2026-10-27 12:00 心跳。巡检【V】组（检测会话里的长 poll）报
`12h 内 309 次长 poll`。我按自己的规则复核，发现**这个会话自己就用了 3 次长 poll**
（180s / 200s / 220s）—— 违反 TOOLS.md 里「poll ≤10~15s」那条规则。

但【V】组**一次都没报我**。

**根因**：【V】组的判据是
```python
job = task_of(head)          # 按 cron 任务标记分类
if not job:
    continue                 # ← 匹配不上就整段跳过
```
`task_of()` 只认 5 个 cron 任务的标记（`scripts/healthcheck.sh`、
`每日学习（精简版）`…）。**普通心跳会话没有任务标记** → 返回 `None`
→ **整个会话被跳过** → 它的 poll 一次都不计数。

而这个盲区是**上一轮刚引入的**：
11:45 那次我为了「按任务维度报告」（daily-learning×12 / backup-audit×9），
把统计从「按会话」改成了「按任务」——
**分组是为了更好的展示，却顺手变成了只统计「认得出来」的那几类**。

**教训（两层）**：
1. **分类不该等于过滤**。分组的目的是展示，不是排除未知类别。
   「匹配不上」应该是「归入『未分类』」，不是「不算」。
2. **断言自己的覆盖面也是断言**。
   一个只统计「已知类别」的断言，等于**对未知情况完全失明**——
   而未知恰恰是最需要被看见的那部分。

**同日还查出【V】的两个隐性错误**（都是「看起来很合理」的那种）：
| 错误 | 表现 | 真因 |
|---|---|---|
| 窗口写着「12 小时」，代码是 3 天 | 说的和做的不一致 | 手写常量漂移 |
| 用文件 mtime 过滤窗口 | 3 天前的违规被算进「12 小时」 | 一个**一直在追加**的会话，mtime 永远是「现在」 |

第三个错最隐蔽：会话文件会持续追加，所以 `mtime` 判龄**永远等于现在**，
导致窗口过滤**完全失效**。必须按**每条记录的 timestamp** 过滤。

**✅ 已做**：
1. 【V】不再跳过任何会话 → 匹配不到归入 `heartbeat/其他`
   → **一次抓出 267 次以前完全不可见的违规**
2. 窗口改用**每条 poll 的时间戳**（不再用文件 mtime）
3. 报告加**按会话归属 + 最后一次违规时间**
   → 一眼分清「还在犯」和「已经停了」
4. `task_of()` 同时匹配**转义形式**（JSON 里非 ASCII 可能变成 `\uXXXX`）
5. **新增【W】组：判据自身的单测**（`scripts/test_v_poll_assertion.py`，9 个用例）

**【W】是这轮最值钱的一条**：
【V】今天连修三个 bug，而【V】报的是「长 poll 数量」——
**判据坏了，它照样输出一个看起来正常的数字**。
典型的自指陷阱：**坏掉的断言看起来和好断言一样正常**。
所以判据逻辑必须有独立单测，而且单测要**直接跑真身代码**：
`test_v_poll_assertion.py` 从 `healthcheck.sh` 的 PY9 块里**抽取真身**来跑
（不是抄一份）→ 判据改了单测立刻跟着变，**物理上无法漂移**。

> 第一版单测就是「抄了一份判据」，
> 而真身已经改成两行写法（`if not job: job = ...`）—— 抄版和真版**悄悄漂移**了。
> 抄一份判据来测 = 测的是「我以为的判据」，不是「在跑的判据」。

**岔路口**：
- ❌ 「把规则写进 TOOLS.md 就行」—— 那是**说明**，不是**约束**（E41/E31 老问题）
- ✅ 让违规**自动可见**：断言负责「发现」，单测负责「保证发现能力没坏」
- ✅ 更进一步：让**约束可执行**（工具层直接拒绝长 poll），但那要改 OpenClaw 本身，
  成本高 —— 先把「可见性」做扎实

**验证**（双向）：
- 真身单测 9/9 通过（现在 / 13 小时前 / 短 poll / 无标记会话 / 转义标记 / 原始中文 / 缺时间戳）
- 全量巡检 PASS=65 FAIL=3（3 项全是长期项）
- 【Q】组当场抓到「新组【W】没同步进 cron 指令」→ 同步后修复 ✅
  （**新加一组断言必然要同步说明文档** —— 这正是【Q】存在的意义）


**同族的三个「断言看起来在干活」**：
E42 讲**数据源**错了 · E45 讲**时间**上是旧数据 · E48 讲**覆盖面**漏了一类
→ 三条都不报错，都给出一个合理的数字 —— **最危险的失败模式**。

**判据本身也要有单测**：坏掉的断言看起来和好断言一样正常。

**延伸**：E42「断言量错了东西」讲的是**数据源**；
E45「监控还在量修复前的那次测量」讲的是**时间**；
E48 讲的是**覆盖面** —— 三条都是「断言看起来在干活，其实没在看该看的东西」。
共同点：**它们都不报错，都给出一个合理的数字。**
