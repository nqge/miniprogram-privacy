### E33：跨过零点还在写昨天 —— 时间线失真比丢内容更隐蔽

> 本条讲：**跨过零点还在写昨天 —— 时间线失真比丢内容更隐蔽**

**场景**：2026-10-27 凌晨 02:30 收尾检查时，发现 `memory/2026-10-26.md`
里混着 **10-27 的内容** —— E29 到 E32 五个小节（00:35–02:16 写的）
全都追加在 10-26 那个文件里。

**为什么隐蔽**：内容**一点没丢**，检索也**完全正常**（搜到的还是对的），
Git 历史也**连续**。没有任何一个「失败」信号。
但：
- 「10-26 的日志」里写着 10-27 的事 → **时间线失真**
- `daily-learning` 09:00 要「读最近 2 天日志」→ 会读到**日期错配**的内容
- 索引里 10-26.md 占 72 块，其中 30 块属于 10-27 → **单文件虚胖**
- 以后回看「10-26 那天做了什么」，会拿到错的东西

**陷阱**：我**每次追加时用的都是硬编码路径** `memory/2026-10-26.md`
（会话开始时算出来的），跨过零点后**没人重新判断**。
这不是 bug，是**默认行为** —— 会话不知道自己跨日了。

**岔路口**：
1. **跨零点后要重新确认「今天」**：写之前用 `date +%F` 取一次，
   不要沿用会话开始时的日期
2. 加断言**自动检测**：某个 `memory/YYYY-MM-DD.md` 里的小节标题日期
   **晚于文件名** → 说明写错文件了
3. **判据设计要看第一版**：
   - ❌ 第一版：全文搜日期 → **大量误报**
     （10-25 的补记里合法地提到 10-26；10-24 提到 10-26）
   - ✅ 正确：只看**小节标题**里的日期，且必须**晚于**文件名
     → 7 个历史文件**零误报**，用拆分前的备份能精确抓到 5 个越界小节
4. **验证靠还原历史状态**：把文件还原成拆分前 → 断言必须 FAIL → 再恢复

**证据**：
- 拆分：10-26.md 1331 → 1139 行（68K），新建 10-27.md 196 行（12K）
- **内容完整性**：拆分后两文件非空白字符 36417 = 原 36337 + 新文件头 90，
  原文内容**全部保留**（关键词 E29/E30/E31/E32/mark_distilled/【O】全在 10-27）
- 索引最大占比 **46% → 31%**（拆分反而改善了均衡）
- L1 检索自检 **32/32** 不受影响；搜 10-27 的内容能命中 `memory/2026-10-27.md`
- 【P】断言：还原到拆分前 → **正确 FAIL**；恢复后 → PASS ✅

**延伸**：这是 E32「派生数据会过期」的**时间维度版本** ——
E32 讲「数字会过期」，E33 讲「**日期会过期**」。
共同点：**会话里的隐含上下文（今天几号、写到哪个文件）会随时间漂移**，
而这种漂移**不产生任何错误信号**，只能靠显式检查发现。
