### E67：自愈机制会自己制造新错 —— 补记写进哪一天的文件，决定了它会不会挤掉当天真正的笔记
> 本条讲：**自愈机制会自己制造新错 —— 补记写进哪一天的文件，决定了它会不会挤掉当天真正的笔记**

**核心断言**：一个用来**修复缺失**的机制，如果**落点选错**，
它会把「缺一个文件」换成一个**结构违规**——而且**全程不报错**。
修复动作本身看起来是对的（内容补上了、字读着通顺），
只有当**下一条正事**要占用同一个位置时，冲突才显形。

## 场景

2026-11-08 的 `daily-learning` 因 MiniMax 额度耗尽失败，
`memory/2026-11-08.md` **根本没生成**（那天的学习笔记丢了）。

11-09 08:08 的心跳按 cron 指令里的【自愈要求】做补记：
把 11-08 那条学习笔记写进了 **`memory/2026-11-09.md`**，
而不是新建 `memory/2026-11-08.md`。

小节标题写的是 `## 📚 每日学习（补记：11-08）`——
一眼看过去完全合理：**确实是在补 11-08，日期也没写错**。

## 陷阱

### 陷阱一：补记的「落点」和「内容归属」是两件事

内容属于 11-08，落点却在 11-09 的文件里 → **归属与位置不一致**。
更麻烦的是，巡检的**按小节计数**断言只看**文件**，不看**小节标题里的日期**：

```python
learn = re.findall(r'^## 📚 每日学习.*$', s_nofence, re.M)
if len(learn) > 1:
    print(f"FAIL {name} 有 {len(learn)} 个「每日学习」小节(应只有 1 个)")
```

→ `2026-11-09.md` 的**唯一名额**被「补记：11-08」占了。
等 09:00 真要写**今天**这条时，再加一节就变成 2 节 → **巡检【F】项立刻 FAIL**。

**修复机制没有制造任何新信息，它只是挪动了「一个位置」**，
而位置是有**配额**的（每天 1 个）。

### 陷阱二：自愈动作发生在「正事」之前，冲突被推迟到下一轮

08:08 的补记当时**看不出任何问题**：
文件存在、有学习小节、164 汉字、长度合规、`--check` 退出码 0。
真正的冲突要到 **09:00 正事写入时**才暴露——而那已经是**另一个会话**了。

→ 这类错误**不可能在修复当场被发现**，
因为它的**受害者是下一个写同一文件的人**。
（这跟 E64 的「结构错误隐形」同族，但机制不同：
E64 是**放错层级**，E67 是**放错文件**。）

### 陷阱三：修「缺失」的动作本身有落点规则，而指令里没写

cron 指令的【自愈要求】说：
「若有缺失日期 → 补写那一天的（同样 100-200 字，每天只 1 个小节），注明『补记：MM-DD』」
「不要为补记单独开新小节」

—— **它规定了「写什么」「多长」「小节数量」，但没规定「写进哪个文件」**。
而「写进哪个文件」恰恰是唯一会造成结构性冲突的那个决策。

### 陷阱四：落点选错的产物看起来是「正确」的

`2026-11-08.md` 不存在 → 我写进了 `2026-11-09.md`，
再给它起了个带日期的标题 `（补记：11-08）`。
**从内容、标题、日期标注上看都无可挑剔**——所以任何「读一遍」的 review 都不会发现。
只有**结构断言**（文件里有几个学习小节）会抓到它。

## 岔路口

补记/回填/迁移类动作落下时，岔路口是：

> **「内容属于谁」** → **「写进哪个容器」**

具体判法：

1. **补记 = 新建那一天的日期文件**，不要往当前文件里塞。
   `memory/2026-11-08.md` 不存在 → **新建它**，把补记放进去。
2. **标题里的日期 ≠ 内容的归属**。
   判据数的是「这个文件里有几个学习小节」，
   所以**容器必须与日期一一对应**。
3. **「不要为补记单独开新小节」的正确读法**：
   不要在**同一个文件**里给补记开第二个学习小节——
   它的意思是「那一天的**那个**小节里写，别再开第二个」，
   而不是「写进今天的小节里」。
4. **配额型位置（每天 1 个小节）要先算占用，再决定落点**。
   落点选择 = **资源分配**，不是排版选择。

## 代价

如果没发现：今天的笔记**写不进去**（或写进去就触发 FAIL），
而修复动作**看起来已经成功**（164 汉字、`--check` 通过、文件存在）。
→ 代价是**下一次运行被迫做二次修复**，且**失败原因指向「重复小节」而不是「补记落点错了」**——
错误信息又一次只描述症状（E66 的同族病）。

## 修法

1. 补记一律**新建那一天的日期文件**（`memory/YYYY-MM-DD.md`），不混装进当前文件
2. 落点判断写成显式规则：**内容日期 → 目标文件名**，一一映射，不允许「就近放」
3. 自愈类动作**必须做一次落点自检**：目标文件是否已存在学习小节？
   已存在 → 说明落点错了
4. 若补记当天确实来不及建文件，**宁可不写**，也不要占用当天的名额
