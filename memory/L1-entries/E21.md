### E21：修症状 ≠ 修类
> 本条讲：**修症状 ≠ 修类**

**场景**：修完一个 bug。
**陷阱**：把「这个具体问题」修好就收工 → 同一类的下一个问题照样会静默发生。
**岔路口**：修完立刻问「**这一类风险还有哪些地方没覆盖？**」，
用一个检查**覆盖整类**，而不是每次出一处补一处。

**证据**：2026-10-26
我修了「重写 .service 把 `OnFailure=` 弄丢」这个**症状**（恢复指令 + 加一条断言），
但没问「『配置文件里的东西 ≠ 实际生效的东西』这一类风险覆盖到了吗」——
换个单元、改个路径，同样会静默失效。
于是又做了 `scripts/check_unit_drift.py`，把这一类系统性覆盖：
单元 enabled / 脚本存在 / 关键指令生效 / 解释器存在 / 定时器调度 / 敏感文件权限。

**怎么破**：
1. 修完先问「这是**个案**还是**一类**？」
2. 是类 → 找一个能**同时覆盖多个实例**的检查点
3. 新检查点**必须做注入故障验证**（否则它自己可能有盲区）

**代价对比**：个案修复 = 一次；类覆盖 = 一次 + 一个检查脚本，
但**同类问题再也不会复发**。
