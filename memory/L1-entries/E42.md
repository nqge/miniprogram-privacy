### E42：断言量错了东西，就等于没有断言

> 本条讲：**断言量错了东西，就等于没有断言**

**场景**：2026-10-27 07:55。daily-learning 的 cron 跑完，巡检报
「2026-10-27.md 小节超长 2010 字（约束 100-200 字）」→ FAIL。
但我核了一下，那一节**我刚压缩过**，而且内容看着不长。

**第一个 bug —— 量的不是规则说的那个量**：
| | 规则（任务指令） | 断言（healthcheck） |
|---|---|---|
| 口径 | 「100-200 **字**」= 100-200 **汉字** | 「去空白后的**所有字符** > 1200」 |
| 实际 | 991 汉字 | 2010 字符 |

→ **两个口径不一致**，断言比规则宽了 10 倍。
→ 结果：10-21 的 568 汉字、今天的 991 汉字**全被放过**，
直到今天凑到 2010 字符才触发 —— 而按规则早就超了 5 倍。
**更糟的是它给出 PASS**：一个量错了的断言报出来的 PASS，什么都不证明。

**第二个 bug —— 边界算错（今天才暴露）**：
小节结尾用 `(?=\n## |\Z)` 找 —— **只认 `##` 级标题**。
而今天「📚 每日学习」恰好是文件里**最后一个 `##` 级标题**，
后面那些 `### 心跳` 小节就被全算进学习正文：
→ 学习小节被算成 **946 汉字**（实际只有 **177**）。
→ 而 `###` 明明是 `##` 的**子节**，本来就属于上一个 `##`。
→ 修法：小节在**下一个任意级标题**（`#{1,6}`）处结束。

**陷阱**：
- 「断言失败了」→ 先怀疑**断言本身错了**，别急着改被测的东西
  （我第一反应是「cron 又超长了」，其实是断言算错了）
- 「量得越宽越安全」→ **反了**：宽的口径等于没有口径，
  而且报出来的是 **PASS** —— 绿色的、什么都不证明的（和 E38 一模一样的形状）
- 「边界用同级的标题就够」→ 层级是**包含**关系，
  子节必须被算进父节的范围里（E38 的「只查今天」也是范围写窄）

**岔路口**：
1. **断言的判据必须和规则的措辞同口径** ——
   规则说「字」就用「字」的定义（中国文里 = 汉字），
   别自己换成「所有字符」还以为是宽松
2. **写判据时先问「我量的是不是规则说的那个东西」** ——
   口径不一致时，**宽的比严的更危险**（宽 = 静默放过）
3. **边界要用「下一个任意层级」**，不要只想同级 ——
   `###` 属于 `##`，把它当边界会漏掉子节的内容
4. **断言报 PASS 时，也要问「这个 PASS 覆盖了哪些东西」** ——
   报告里带上「已查 N 个文件」（E38 已加），
   长度类判据也该报出**用的什么口径**

**证据**：
| 项 | 改前 | 改后 |
|---|---|---|
| 长度判据 | 全字符 > 1200 | **汉字 > 400** |
| 小节边界 | `\n## `（只认同级） | **`\n#{1,6} `（任意层级）** |
| 今天学习小节 | 被算成 946 汉字 | **实际 177 汉字** ✅ |
| 10-21 学习/反思 | 568 / 491（放过） | **252 / 227**（已压缩合规） |
| 能抓到的真实违规 | 几乎抓不到 | **3 处（含 2 处历史）** |

**延伸**：E38 讲「只查今天的检查会漏掉历史违规」，
本条讲「**查了但量错了**」——
两者都产出**绿色的、什么都不证明的 PASS**，
区别只是前者是范围窄，后者是口径错。
合起来：**断言的三要素 —— 范围、口径、边界 —— 任何一个错，PASS 都是假的。**
