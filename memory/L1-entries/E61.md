### E61：入库脚本的「剥」和「装」必须用同一个真相源 —— 否则作者原话会被静默改写
> 本条讲：**入库脚本先剥掉关键词、组装时又拿不到它，就会退回用标题覆盖作者原话**

## 场景

写「把一条经验写进两个地方（独立文件 + 主库）」的入库脚本时，
流程天然分两步：**从源文件剥出正文** → **组装成目标块**。

2026-11-04 实测（`scripts/add_l1_entry.py`）：主库 60 条里有 **5 条**
（E55/E56/E57/E59/E60）出现了**重复的「本条讲」行**，E60 甚至有 **3 行**。

## 陷阱

两个独立缺陷叠在一起，互相掩护：

**缺陷 A —— 组装端无条件注入**
```python
block = f"{heading}\n\n> 本条讲：**{title}**\n\n{body}\n"   # ← 注入
```
但 `body` 里**本来就带作者的「本条讲」行** → 主库变成 2 行。
E60 的源文件有 2 行 → 变成 3 行。

**缺陷 B —— 剥除端只剥一行**
```python
re.sub(r"^###\s*E\d+[：:].*$\n+\s*^> 本条讲：\*\*.+?\*\*\s*$", "", text, ...)
```
这个模式**锚定在标题行之后**，只能命中标题后**紧邻**的那一行。
作者若写了第二行（E60 就是这样），第二行**残留进 body** → 叠加缺陷 A → 3 行。

**更隐蔽的一层（差点自己踩进去）**：
我第一版修法是「剥掉所有本条讲行」+「body 里有就沿用作者的，没有才用标题补」。
但流程是**先剥后装** —— 剥掉的关键词**没传给组装函数**，
组装时发现 body 里没有 → 退回用**标题** →
**E58 的作者原话「lastRunStatus 是单点快照…」被静默改写成标题**。

> **一个工具「修好了重复」，同时「改掉了内容」——
> 而重复是看得见的，改写是看不见的。**

## 岔路口

剥与装之间**必须有一个显式的真相传递**：

```
peel_body(text, eid) -> (body, kw)      # 剥下来的关键词一起返回
build_block(eid, title, body, kw)        # kw 优先，没有才用 title 兜底
```

配套三步：
1. **剥**：剥掉**所有**「本条讲」行（不只一行），同时记住第一行内容
2. **装**：优先用传下来的 `kw`（作者原话）→ body 里残留的（兜底）→ 都没有才用标题
3. **断言**：每条主库条目必须**恰好 1 行**「本条讲」——多于 1 行和 0 行都是坏数据

## 证据

- 修复前：主库 5 条重复（E60 三行），独立文件 E60 两行
- 修复后：60 条**全部恰好 1 行**，作者原话 100% 保住
- 新增单测 `scripts/test_add_l1_entry.py`（14 用例）：
  - 剥除端剥所有行 / 保正文 / 不留标题行 / 关键词要传下去
  - 组装端恰好 1 行 / 作者原话优先 / 无 body 时兜底 / 幂等
  - 回归：主库 60 条各 1 行 + 独立文件各 1 行
  - **判据自检**：用故意写坏的输入验证断言**能抓得到**（防断言装死）
- `verify_l1_retrieval.py` 60/60 PASS

## 迁移成本

本条是**第 4 次**「入库脚本自己的替换逻辑与它写入的结构不一致」：
- E52：stub 标题重复
- 2026-10-29：正则跨不过嵌套标题（一条变三条）
- 2026-11-04 缺陷 A+B：重复「本条讲」行 + 作者原话被覆盖

**规律**：入库脚本是「渲染源」—— 它写错的内容会被下一个会话**直接当成事实继承**，
所以它的判据必须和它写入的结构**同源**，不能各写一份。
本次的做法是**单测直接 import 被测模块**（不抄判据），
并加一条「用坏输入验证断言能抓到」的判据自检。
