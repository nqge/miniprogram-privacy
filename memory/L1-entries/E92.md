### E92：改了判据就要重算历史结论，旧结论不会自己变
> 本条讲：**改了判据就要重算历史结论，旧结论不会自己变**

**核心断言**：当你把一个判据的**输入口径**改了（多读了一个字段、
收紧了一个阈值、换了一个归日基准），
**所有由它产出的历史结论都作废了 —— 但它们不会自动消失**。
必须**主动重算一遍**，把旧结论**替换**掉。
**判据升级 ≠ 结论自动更新。**

> **分类**：认知与判断 / 系统维护
> **首次记录**：2026-11-28
> **来源**：E91 的落地侧 —— 巡检报「3 天额度耗尽」，实为 1 天

---

## 场景

任何「判据 → 汇总数字 → 结论（要不要告警 / 要不要充值）」的三段式链路：

```
原始事件 → [判据] → 汇总数字 → [结论]
                ↑              ↑
           改这里 →      这里的结果全作废
```

## 触发条件

改判据时，**只要动了输入口径**，就必须重算：

- 读入的字段变了（`state` → 也读 `detail`）
- 阈值变了（3 天 → 5 天）
- 归组基准变了（`ts[:10]` → `to_local_date()`）
- 匹配方式变了（精确匹配 → 正则 / 分级）

**不变的只有**：只读输出、不再参与计算的旧结论。

## 本次实例（2026-11-28）

E91 诊断出：`state == "quota_exhausted"` 一个标签下装着三种强度不同的证据，
而判据**只读 `state`、从不读 `detail`**。

改造前，07:00 巡检报：
> ⏳ 最近 7 天里有 3 天额度耗尽（2026-11-22、11-23、11-27）—— 需要牛哥哥充值

改造后（判据加了证据分级，只认带 `request_id` 的原始凭据）实跑：
> PASS 最近 7 天**确认**额度耗尽 1 天（<3 天）
> INFO 另有弱证据耗尽记录（不计入结构性不足结论）：L1未证实 2 天

**逐条核对真实数据**：

| 级别 | 次数 | 分布 |
|---|---|---|
| L3 确认耗尽（原始 Token Plan 凭据 + request_id） | 2 次 | 全在 11-27（同一天）→ **确认 1 天** |
| L1 未证实（"额度特征命中"字符串匹配） | 11 次 | 11-14～11-23 → 窗口内 2 天 |
| L0 矛盾信号（"没有任何可用 provider"） | 13 次 | 全在 10-30～11-09 → 窗口外 |

→ 巡检的「等你」项从 **2 条降为 1 条**，那条额度充值请求**消失了**。
**这不是故障消失了，是结论本来就不成立** —— 拿标签推出来的 3 天去要充值，
是拿噪声当证据。

## 为什么这条重要

E91 只诊断出「结论是标签推出来的，不是证据推出来的」，
但**光诊断不重算，那条错误的「等你」会一直挂在那儿**，
而且下次巡检还会用新判据跑出「新数字」——
但**没人知道历史结论已经作废了**，新旧两个结论并存，比只有错结论更糟。

## 落地做法

1. 改判据后**立刻用真实数据实跑一遍**，看输出变成什么
2. **逐条核对**分级的分布（不是只看汇总数字）
3. 检查**下游**有没有依赖旧数字的地方（巡检报告、SESSION-STATE、告警去重）
4. 在 L1 里记「改了什么口径 → 旧结论是什么 → 新结论是什么」

## 陷阱

- **别只改判据不复算**：旧结论留在日志/文档里，下一个会话会当成事实继承
- **别只复算不核对分布**：汇总数字对了但分级全归一类，等于没分
- **窗口会藏数据**：L0 那 13 次全在 7 天窗口外 —— 改判据后要**看全量分布**，
  否则会误以为「L0 从来没出现过」而删掉那套分级逻辑
