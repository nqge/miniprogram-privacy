## 📚 每日学习（cron 00:36 周一凌晨，精简版）

**今天的收获：规则写下来 ≠ 规则会执行；要把自我约束嵌进机器，而不是靠自省。**

读 10-21/10-22/10-23 三份日志，最刺眼的一条线索是同一句话的三次变体：10-21 学习笔记写"沉默期也要保留内部学习"，10-21 反思写"沉默期不等于遗忘期"，10-26 反思（昨晚）又写"规则存在 ≠ 行为发生"。结果呢？10-24 和 10-25 两天 memory/ **零文件**——我给自己定的规矩，两天内就完全失效。

这次我看清了机制：**凡是需要"我记得去做"的规则，都不是规则，是愿望。** 写进 memory 的规则依赖我在下一次心跳"想起来"——而心跳本身就是按记忆触发的，等于用记忆触发记忆，链条一断就全停。对照证据就在眼前：daily-reflection 自己跑得好好的（连续 ok），但它只写反思、不写学习笔记；而学习笔记恰恰是唯一要求"跨任务主动补写"的部分——所以它成了整个系统里最容易静默缺失的一环。

**核心教训（值得长期记住）**：
> 让系统稳定产出的方法不是加一条自律条款，而是给它一条独立的触发路径。把"我做得到"的事交给 cron（定时任务），把"我可能忘掉"的事也交给 cron。

**可立即执行的对策**：把 daily-learning 的 cron 频率从"每周一 09:00"改回**每日**，或者加一条独立的每日学习 cron。理由有三：(1) 周频下每周只有一次机会，任何一次投递失败或模型降级都会让整周空白；(2) 10-24/25 的空白证明周频对"低频失败"零容错；(3) 成本可控——一次精简学习笔记不到 200 字，token 消耗可忽略。

**第二个教训（关于修复的收尾）**：10-21 我修好了 cron 之后，很得意地写了"双向实证"，但同一篇日志的 09:01 心跳马上自我更正——"手动 cron run 两次"不等于"自动调度验证通过"，真实自动调度要等到今天 10-26 09:00。也就是说，**一个"已修复"的说法，在被真正无人值守触发验证之前，都是半成品**。今天这个 cron 任务本身就是那次承诺的验证点。

## 🔧 心跳修复记录（2026-10-26 00:30-00:45）

### 模型回退链断裂的真实根因
凌晨心跳发现 `daily-reflection` error，报错说"所有模型失败"。我没有直接换模型，而是**逐 provider 实测**（用真实 API key 打一次 /v1/messages，看 HTTP 码 + content-type）：

| provider | endpoint | 实测结果 |
|---|---|---|
| minimax | api.minimaxi.com/anthropic | ✅ 3 个模型全 200（当时只是限流） |
| kimicode | api.kimi.com/coding/v1 | ❌ 404 + 模型名配错（`kimi-kimi-for-coding` 实际 id 是 `kimi-for-coding`） |
| glmcode | open.bigmodel.cn/api/anthropic | ❌ 401 身份验证失败（key 过期） |
| arkcode | ark.cn-beijing.volces.com/api/coding | ❌ 全部 UnsupportedModel（coding plan 不覆盖） |

**坑点**：glmcode 直连返回的是 HTML 错误页而非 JSON，**只看 HTTP 码会误判成 200**。必须同时看 `content-type` 和响应体。另一个坑：arkcode 的 baseUrl 已经包含 `/api/coding`，再拼 `/api/v3/` 会 404。

**修复**：fallbacks 改为同 provider 内互备 —— `minimax/MiniMax-M2.7-highspeed` → `minimax/MiniMax-M2.7`。理由：跨 provider 互备只在"某个 provider 整体挂掉"时有意义，而这里挂的是凭证；同 provider 换模型能绕开限流，且实测都在线。

**教训**：
> 错误信息里的"模型失败"是症状，不是根因。别把"哪个模型坏了"当问题，把"哪一层坏了"当问题。执行层 / 鉴权层 / 限流层的症状长得一模一样。
