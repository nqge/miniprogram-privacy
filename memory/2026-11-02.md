## 🧠 新教训（候选 L1）

### E56 候选：别在脚本运行时改它
- 现象：systemd 正在跑 `healthcheck.sh`，我同时往脚本里插了一段 → bash 按**字节偏移**读脚本，
  插入导致后面读到错位 → `syntax error near unexpected token` → 这次巡检直接崩（EXIT=2）
- 教训：**脚本是流式读取的**。「改完再跑」和「边跑边改」不能共存
- 判据：改脚本前先看有没有在跑的实例（`systemctl --user list-units 'openclaw-*'`）

### E57 候选：额度型依赖，「变慢」和「耗尽」是两套机制
- E39 讲的是「变慢」（共享配额被抢）→ 无 error、只是慢、难归因
- 这次是「耗尽」→ **明确的 429 + 明确的中文报错文案**（「已达到 Token Plan 用量上限」）
- 关键区别：**耗尽时 fallback 链必然同时失效**（同账号同额度桶）→ 所以看到 429 就该立刻查额度，而不是继续试模型
- 预防：**别让纯脚本任务依赖模型额度**（E8），额度一耗尽，「体检」本身会先死
