### 起因
例行读 SESSION-STATE.md 头部，发现状态行写着：

### 真正的结构（agent 级目录 vs 全局配置）
OpenClaw 有**两层** provider 配置：
| 层 | 文件 | `models.mode=merge` 下的作用 |
|---|---|---|
| 全局 | `openclaw.json` → `models.providers` | 基础目录 |
| **agent 级** | `agents/main/agent/models.json` → `providers` | **叠加**进最终目录 |

实测证据：
- `openclaw models list`（默认，只看 default/fallback 标签）→ **只有 minimax 3 个模型**
- `openclaw models list --all` → **arkcode / glmcode / kimicode 都在，15 个模型可选中**
- 我今早实测这 4 家的凭证**全部失效**（401/403/400/404）

→ 所以「它们已删除」是**错的**：它们**仍在最终目录里、仍可被选中**，只是没被 `primary`/`fallbacks` 引用。
→ **决策项依然有效**，不是「已了结」。

### 盲区本身才是真正的问题
`scripts/healthcheck.sh` 的【M】组和 `scripts/gen_system_status.py` **都只读 `openclaw.json`**
→ 于是「本地有 + 运行时能选中 + 凭证已死」的 provider **永远不出现在体检报告里**
→ SESSION-STATE 因此写下「已删除」这种**反向错误结论**
→ **下一个会话读到它，会以为 provider 问题已经了结，不再处理**
这正是 TOOLS.md 里「没查就下结论的错误会在下个会话被当成事实继承」的**活实例**。

### 可复用教训（值得进 L1，但今日学习小节已满，留在这里）
1. **一个系统里有两层配置时，「已删除」先问「删的是哪一层」** —— 本地文件删了 ≠ 全局生效
2. **体检脚本的输入范围 = 它的盲区边界** —— 只读一个配置源，就等于对另一个配置源失明

4. **「已了结」是最危险的结论** —— 它让下一个会话直接跳过问题；
   反过来「仍待处理」只是多花一次确认成本
5. 判据：**看到「已删除/已修复/不再需要」这类结论，先去 stat 一下相关文件的 mtime**
