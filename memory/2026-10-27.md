### 2026-10-27 00:45–01:30 心跳 — 茶馆待办队列只加不减（E30）

**起因**: 跨日边界检查时看茶馆监控状态，发现 `memory/teahouse-todo.json` 的
`pending` 队列里**永远躺着同样 4 条**（#135/#138/#134/#154）——
而它们在 11:30 就已经蒸馏进 `teahouse-digest-2026-10-26.md` 了。

**根因**: `prompt_distillation()` **只追加，从不移除**：
```python
for i in fresh:
    if n in known: continue
    existing["pending"].append(...)    # 只加
# 整个函数没有一句从 pending 里删东西
```
→ 蒸馏完成后**没有任何机制**把条目移出队列 → 每 4 小时重蒸馏同样 4 条。

**为什么巡检没抓到**: 【I】组是**间接**判定（查编号是否出现在某篇笔记里），
**从不检查队列本身** → 巡检报「茶馆内容已全部蒸馏」✅，
而队列里明明还挂着 4 条 ❌ —— **两个状态互相矛盾，巡检只信了对自己有利的那个。**

**✅ 已做**:
1. `teahouse_monitor.py` 新增 `mark_distilled()`：
   - 已蒸馏条目移到 `distilled` 列表（保留编号/标题/时间，可追溯）
   - `distilled` **限量 50 条** —— 否则只是把「只增不减」换了字段
   - CLI: `--mark-distilled <编号1,编号2>`，省略编号 = 自动标记
2. `healthcheck.sh`【I】组加**队列自洽性检查**：`pending ∩ distilled == ∅`
3. cron 指令加「【蒸馏完必须出队】」一段（含 E30 引用）

**⚠️ 修的过程中差点得出错误结论**：我先查 `seen_ids` 发现 #135 不在里面，
以为「修复会被 4 小时后推翻」→ 其实去重键是 `seen_numbers`（议题号），
4 条**都在**里面。→ **查字段前先确认字段语义**。

**验证（双向）**:
- 端到端跑真实监控 → 「无新内容」，`pending` 保持 0，`distilled` 4 条 ✅
- 注入「#135 同时在 pending 和 distilled」→ **正确 FAIL** ✅
- 正常态 → PASS（显示已蒸馏数）✅

**新增 E30** 入库（30 条，30/30 可检索）：
「队列型状态只加不减 = 每次运行都在重复劳动」

### 2026-10-27 01:10–01:50 心跳 — 把「出队」从指令变成机制（E31）

**起因**: 修完 E30 后发现自己的修复**留了个洞**：
E30 的根因是「出队这一步靠人记得做」，而我只把这一步**写进了 cron 指令**
—— 指令是提示，不是机制。agent 忘了/跑歪了，bug 原样复发。

**而且巡检查不出来**：原来的【I】组逻辑是
```
still = [pending 里【没】出现在任何笔记的条目]
if still: FAIL    # 真未蒸馏 → 该报
else:      PASS    # 已出现在笔记里 → 报 PASS，但【不清理】
```
→ 「已蒸馏但没出队」这个 E30 的 bug 状态**恰好落在 PASS 分支**里。

**✅ 已做 —— 巡检自愈**:
检测到「pending 里的条目已出现在某篇笔记里」→ **主动移出队列并记入 distilled**
→ 出队不再依赖任何人记得做。

**自愈与告警严格分开**:
| 情况 | 处理 | 理由 |
|---|---|---|
| 已蒸馏但没出队 | **自愈**（自动移出） | 本来就是对的，只差个出队动作 |
| 真未蒸馏 | **FAIL 告警** | 真的需要人做事 |

**⚠️ 自己踩的坑**: 自愈逻辑第一版把 `still`（=**没**出现在笔记里的）
当成了「已蒸馏」→ **方向完全搞反** → 注入 #135 后自愈了 0 条。
→ 变量名改成 `in_notes` 语义明确的写法；**反直觉命名最容易把逻辑写反**。

**⚠️ 第二个坑**: 自愈刚改过文件，后面的一致性检查继续用内存里的旧数据
→ 报出「刚自愈完又说矛盾」的假 FAIL → 改成**重新读盘**。

**验证（三个方向都测了）**:
- 注入 E30 原始 bug 状态（#135 已蒸馏但仍在 pending）
  → 「自愈：1 条已蒸馏但未出队 → 已移入 distilled [135]」，pending 归 0 ✅
- 注入真未蒸馏条目（#999，笔记里不存在）→ **仍 FAIL** ✅（自愈没掩盖真问题）
