### 二、E78 的修法落地

E78 讲的是：**任何以「连续 N 次」为阈值的判据，都必须同时检查这 N 次跨越了多长时间**。
`check_gate_skips.py` 的 `FAIL_CONSECUTIVE = 3` 语义是「连着 3 天枯竭」
（证据在它自己的单测里：三条假数据写成 11-16/11-17/11-18 三个自然日），
但实现**只数条数**（`cur += 1`），**从不看时间跨度**。

**改法**（三处）：
1. 新增常量 `SPAN_MIN_DAYS = 2` / `SPAN_MIN_HOURS = 6`，
   并在 `FAIL_CONSECUTIVE` 旁边**写清楚单位是「3 条记录」不是「3 天」**；
2. 计算那段连续跳过的**首末时间戳 + 自然日跨度 + 小时跨度**，
   判定 `sustained`（条数够 **且** 跨度够）；
3. 报「连续 N 次」时**把首末时间戳一起打出来**（E78 教训③）。

**关键分支**：条数够但跨度不够 → `retry_only` → **只报 WARN，不占用额度告警名额**。

**单测**：新增 2 个用例 ——
2b) 同一天 27 分钟内 3 次重试 → **不应** FAIL（`retry_only=True`，`span_ok=False`），
    且措辞必须含首末时间戳 + 「E78」；
2c) 首末间隔 >6 小时 → 应算持续枯竭（`span_ok=True`）。
→ `python3 scripts/check_gate_skips.py --self-test` ✅ 全部通过。

**实测前后**（真实数据）：
- 修复前：FAIL「最近曾连续 3 次被闸门跳过（截至 …，现已恢复）」→ 占用额度告警名额
- 修复后：WARN「曾连续 3 次被闸门跳过，但**跨度仅 2026-11-17-090032 → 2026-11-17-092823
  （仅 0.46 小时 / 1 个自然日）** → 这是**一次事故的重试**，不是持续枯竭」
