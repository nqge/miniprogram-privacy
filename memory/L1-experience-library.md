# L1 经验库 — 可复用的方法论

> **来源**：龙虾茶馆 #135「小隐的三层记忆架构」——
> L0 工作记忆（当日日志）/ **L1 经验记忆（经验总结、常用模式）**/ L2 永久记忆（`MEMORY.md`）。
> 2026-10-26 建立。之前 L1 和 L0 混在每日笔记里，经验无法跨日复用。
>
> **与 L0 的区别**：
> - L0（`memory/YYYY-MM-DD.md`）= **今天发生了什么**，流水，任务结束即失效
> - L1（本文件）= **我学到的方法论**，可跨日复用，每条都有触发条件
> - L2（`MEMORY.md`）= **关于用户和长期决策的事实**
>
> **收录标准**：① 换一个场景仍然成立 ② 能指导具体动作 ③ 有明确的触发条件
> —— 三条都不满足的，只是流水，留在 L0。

## 🔧 排查方法论


### E1：区分「失败」和「没触发」
> 本条讲：**区分「失败」和「没触发」**

**场景**：定时任务没产出结果。
**陷阱**：看到没产出就归因为「任务失败了」→ 去查日志、查错误码 → 什么都查不到 → 记为「已知残留项」。
**岔路口**：先查 **cron runs 历史**（有没有触发记录）→ 有记录 = 失败（查日志）；没记录 = 没被调度（改频率/查调度器）。
**证据**：2026-10-26，`daily-learning` 10-24/10-25 零产出。查 runs 历史发现
**10-19 之后到 10-26 之间零次触发** —— 不是失败，是根本没跑。


### E2：口径不一致的对比会产生假告警
> 本条讲：**口径不一致的对比会产生假告警**

**场景**：比对「本地 vs 远端」文件数。
**陷阱**：一边用 `find`（含运行时垃圾如 `__pycache__`），另一边用 `git ls-tree`（只含被追踪文件）→ 报「漏文件」。
**岔路口**：**先确认两边用同一口径**，再判断差异是否真实。
**证据**：2026-10-26，`backup_audit` 报「scripts/ 远端 8 < 本地 9」，实测 `git ls-files` 两边完全一致。


### E3：清理想删旧文件，先确认判龄信号本身有效
> 本条讲：**清理想删旧文件，先确认判龄信号本身有效**

**场景**：清理按时间轮转的日志。
**陷阱**：用 `mtime` 判断「文件多旧」→ 规则永不触发，而且**看起来一直在正常工作**。
**岔路口**：先验证判龄信号本身（打印每个文件的实际年龄）；轮转方式与文件系统行为不符时，
**唯一可靠信号通常是文件名里的槽位标识**。
**证据**：2026-10-26，OpenClaw 日志轮转**按大小不按天** → 同一槽位跨天追加 → `mtime` 永远新鲜
→ `-mtime +7` 规则一次都没触发过。


### E4：涉及「默认值/协议/常量」的结论，必须查源码或实测
> 本条讲：**涉及「默认值/协议/常量」的结论，必须查源码或实测**

**场景**：判断某个配置项的默认行为。
**陷阱**：读文档或凭印象 → 写进记忆文件 → 下个会话当成已验证事实继承。
**岔路口**：`grep` 源码里的常量定义 / 直接实测。
**证据**：2026-10-26 两次栽在这上面 ——
① 「agentTurn 型 cron 默认 timeout 是 30s」实为 **360s**（30s 是 `apply.runtime` 搜索路径的值）
② 「远端提交已添加 `bin/requirements.txt`」实为**文件根本没提交**。


### E5：提交说明 ≠ 文件真的存在
> 本条讲：**提交说明 ≠ 文件真的存在**

**场景**：判断某个修复是否生效。
**陷阱**：读 commit message 里的「已添加/已修复」就当作事实。
**岔路口**：`git ls-tree` / `git show --stat` 落到**文件层面**核实。
**证据**：2026-10-26，远端 `ad8098d` 声称「添加 bin/requirements.txt」→ `git ls-tree origin/main bin/` 只有脚本。

## 📏 工程取舍


### E6：状态字段 ≠ 用户得到的结果
> 本条讲：**状态字段 ≠ 用户得到的结果**

**场景**：任何「自动化是否正常工作」的判断。
**陷阱**：只看 `status=ok` / `enabled` / `consecutiveErrors=0` → 绿色一片，实际功能全死。
**岔路口**：沿着 **触发 → 执行 → 落盘 → 投递 → 用户看到** 逐段取证，每段单独断言。
**证据**：2026-10-26 一天内四个例子——
① 记忆检索 `enabled` 但 Embeddings unavailable（**从 3 月起就没工作过**）
② 飞书投递 `status=ok` 但结果从未送达
③ 学习笔记不报错但周频让 4/8 天根本不触发
④ 茶馆摘要稳定落盘但 4/15 讨论从未被提炼


### E7：定时器保证触发频率，不保证信息增量
> 本条讲：**定时器保证触发频率，不保证信息增量**

**场景**：设计周期性任务。
**陷阱**：把「每 4 小时跑一次」当成「每 4 小时有新东西」→ 重复产出、浪费存储。
**岔路口**：落盘前与上一份比对，内容相同则跳过。
**证据**：2026-10-26，茶馆 0039 与 0040 两份摘要**全文 1671 行、diff 仅 4 行**（99.8% 相同）。


### E8：纯脚本任务不该用 agent 型 cron
> 本条讲：**纯脚本任务不该用 agent 型 cron**

**场景**：让定时器执行一个 shell 脚本。
**陷阱**：agent 型 cron 为了跑一个 20ms 的脚本，消耗 261 秒的模型往返。
**岔路口**：需要判断的用 agent 型；纯脚本用 systemd timer。
**证据**：2026-10-26，`log-cleanup` 改成 systemd oneshot → **261s → 21ms**。


### E9：收集、存储、加工是三件事
> 本条讲：**收集、存储、加工是三件事**

**场景**：构建「信息采集」类系统。
**陷阱**：把「收集」当成终点 → 数据进磁盘，但从未影响判断。
**岔路口**：加工环节要独立存在（待办清单 + 进度断言），否则收集系统只是**浪费磁盘的订阅服务**。
**证据**：2026-10-26，茶馆 monitor 忠实收集 95 条讨论，**4/15 未被提炼**。


### E10：同一文件里的多个同类小节会指数膨胀
> 本条讲：**同一文件里的多个同类小节会指数膨胀**

**场景**：让 agent「在已有小节内追加」而非覆盖。
**陷阱**：频繁触发 + 追加语义 = 每次跑一次多一节。
**岔路口**：明确规定「每天只允许 1 个小节，已有则**替换/精炼**」；长度写成硬约束并自检。
**证据**：2026-10-26，一天堆出 **6 个学习小节、单节 3365 字**（约束是 100-200 字）——
典型的「反刍」。


### E11：新增断言必须做注入故障验证
> 本条讲：**新增断言必须做注入故障验证**

**场景**：写检查脚本（巡检、校验器）。
**陷阱**：脚本跑出 PASS=20 就认为它有效 —— 它可能内含一个**永远抓不到故障**的分支。
**岔路口**：注入故障（停服务 / 造分歧 / 造未蒸馏）→ 确认它真会 FAIL → 恢复。
**证据**：2026-10-26，9 组断言里 **4 组写完后自己坏过**；
且第一版【I】组把蒸馏稿也算进搜索范围，一直**误判 PASS** ——
**检查自己产出的文件，等于没检查**。

## 🧭 认知与判断


### E12：落盘 ≠ 送达
> 本条讲：**落盘 ≠ 送达**

**场景**：把待办、结论、选项单交给用户。
**陷阱**：写进文件就以为「做完了」→ 文件存在反而带来虚假的安全感。
**岔路口**：每个待办问一句「**他怎么知道？**」—— 答不上来就是没做。
**证据**：2026-10-26，`待决策选项单.md` 在磁盘上躺了 6 周，**从未进入用户视野**。


### E13：机制缺口比单点故障更值得修
> 本条讲：**机制缺口比单点故障更值得修**

**场景**：同时发现多个「功能其实早就是死的」。
**陷阱**：逐个修完就收工 → 下个月同样的问题换个马甲再来。
**岔路口**：修完一个，追问「**为什么现有机制没抓到它**」，把那条断言补进每日巡检。
**证据**：2026-10-26 发现的四个故障，**没有一个**是被原有机制抓到的。


### E14：风险描述不能靠记忆，要靠实测
> 本条讲：**风险描述不能靠记忆，要靠实测**

**场景**：评估某个凭证/配置的风险等级。
**陷阱**：沿用之前的描述 → 用户基于错误前提做优先级判断。
**岔路口**：涉及权限/额度/影响范围时，**实测**（查 scope、查实际权限），不要只复述「是不是明文」。
**证据**：2026-10-26，classic PAT 原记录是「明文落盘」，实测 scopes 含
`admin:org` / `delete_repo` / `admin:enterprise` → 实际是**账号完全控制权**。


### E15：对外收敛 ≠ 对内收敛
> 本条讲：**对外收敛 ≠ 对内收敛**

**场景**：判断某件事该不该做。
**陷阱**：把「用户不在场」当成「可以无限期做」→ 内部学习、笔记、维护一起停掉。
**岔路口**：区分**对外动作**（要克制）和**对内动作**（零成本、不打扰，照常）。
**证据**：2026-10-21 的反思（当时定规矩）→ 10-24/10-25 两天 memory 零文件（规矩失效）。


### E16：低触发频率的机制没有容错
> 本条讲：**低触发频率的机制没有容错**

**场景**：把某个每日任务调成每周/每月以「省资源」。
**陷阱**：低频 = 每次失败就是整周空白，且**空白期往往正是无人注意的时候**。
**岔路口**：频率是**容错参数**，不是省钱旋钮。
**证据**：2026-10-26，daily-learning 周频 → 10-24/10-25 零文件。


### E17：检索的最小单位是「块」，不是「条」——短章节会被切碎稀释
> 本条讲：**检索的最小单位是「块」，不是「条」——短章节会被切碎稀释**

**场景**：新建知识库 / 经验库 / 笔记体系；任何「写下来了但搜不到」的现象（沉淀一条新经验时）。
**陷阱**：验证「文件存在、条目数对、mtime 新」就宣布完成 → 内容**写完即死**。
更隐蔽的一层：检索按 token 切块（`chunking.tokens=200`），**切在条目中间时标题和「场景」被切走**；
短小节夹在两个长小节之间时，标题与正文分处两块，**两块都不以这条内容开头** → 向量被邻段平均掉，
搜原文措辞也排不进去。检索到的是**语义残片**，不是你的条目。
**岔路口**：① 建完立刻拿**原文措辞**检索一次，排不进前列就重写标题/措辞（命中分数是硬指标，不是感觉）；
② 关键条目**首行重复标题关键词**（本文件的 `> 本条讲：` 约定即为锚点），让条目在任意切块下都自洽；
③ 独立条目**拆成独立文件**，彻底摆脱邻段稀释（最有效，见下方证据）。
**证据**：2026-10-26 建立 L1 库（16 条）→ 用原文措辞搜「区分『失败』和『没触发』」，
L1 排第 1（**0.6554**）→ 但新增 E17 后搜「沉淀 验收标准 检索命中」，**E17 所在块没进前 6**；
查库见其被切成 20-45（开头是反思）与 41-57（开头无标题）两块 →
补标题锚点后仍被邻段稀释 → **拆成独立文件 `memory/daily-notes-index.md` 后直连余弦 0.5457 排第 1**
（同查询下旧写法为「未进前 6」）。

### E18：记住了 ≠ 不再踩，要改结构
> 本条讲：**记住了 ≠ 不再踩，要改结构**

**场景**：任何「我刚犯过这个错」「我刚记录过这条教训」的场合。
**陷阱**：把教训写进笔记 / 记忆文件就当解决了 → 同样的错误换个场景再来，
而且因为「我已经记过了」，反而不会再警惕。
**岔路口**：凡是**已经踩过一次**的错误，要改的不是记忆而是**结构**：
- 长文本（尤其含反引号、`>`、`$`）→ 写进文件，用 `--message "$(cat file)"` 引用，不要裸放命令行
- 危险字符 → 用 heredoc（`<< 'EOF'`）而非拼接字符串
- 路径 → 提取成变量，不重复手写
**证据**：2026-10-26 12:15，我给 cron 改指令时在命令行里写了反引号和 `>`：
- 反引号 → **命令替换** → `memory/YYYY-MM-DD.md` 被当命令执行
- `>` → **输出重定向** → `memory/daily-notes-index.md` 被当输出目标
- 两个文件路径**从指令里消失**，而命令**「成功」返回了 JSON**（无报错）
讽刺的是：我 20 分钟前刚把这条写进 E17 那一节的上下文里（「检查自己产出的文件等于没检查」）。
→ **记教训是最弱的改进步骤，改结构才是。**


### E19：bash 里嵌套 heredoc + 命令替换会吞掉变量
> 本条讲：**bash 里嵌套 heredoc + 命令替换会吞掉变量**

**场景**：在 shell 脚本里用 `$(...)` 包一个 heredoc（python 代码），再把结果放进变量。
**陷阱**：变量**静默变成空串**，不报错、不中断。表现是「写进去了，但值是 0/空」。
**岔路口**：把 python 代码抽成**独立脚本文件**，用 `python3 script.py "$arg"` 调用，
不要在 shell 里内嵌 heredoc。需要多参数就全部走命令行参数。
**证据**：2026-10-26 12:20，给 healthcheck.sh 加「自动更新 SESSION-STATE 巡检现状行」时：
```bash
GROUPS=$(python3 - "$SELF" << 'PYEOF'
...
PYEOF
)
NEWLINE="... ${GROUPS} 组断言 ..."
```
`bash -x` 显示 `GROUPS=12` 紧接着 `NEWLINE='... 0 组断言 ...'` —— **变量被吞**。
我试了固定路径（怀疑 BASH_SOURCE 空）、花括号、多字节字符、heredoc 改写，
**换了四种写法都是 0**，直到把 python 抽成独立脚本 `scripts/update_state_status.py` 才通。
**排查耗时超过 10 分钟，且过程中输出一直是「成功」** —— 静默失败最难查的就是这种。

## 📌 维护规则

1. **新经验从 L0 提炼上来**，不是重写一遍。提炼时问：换个场景还成立吗？能指导动作吗？有触发条件吗？
2. **每条必须有「场景 / 陷阱 / 岔路口」三段** —— 这是「岔路口记忆法」的结构（茶馆 #22 讨论引入）
3. **反例也要记**（见 E11 的 4 次自伤）—— 失败教训比成功经验更可靠
4. **定期回看**：某条经验如果很久没用上，要么删掉，要么补充触发条件
5. **标题关键词在正文首行重复一次** —— 检索按 token 切块，切在条目中间会丢掉标题，
   让条目在任意切块下都自洽（见 E17）
